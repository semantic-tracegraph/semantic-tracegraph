What this is

Analyzing agent traces helps us understand their capabilities, failure modes, and potential inefficiencies. Most agent evaluations use a final pass/fail outcome for simplicity, but that outcome ignores useful intermediate work, especially in failed trajectories. As agents take on more complex tasks, a single trajectory can contain several task-relevant accomplishments. Measuring those accomplishments provides a richer view of agent behavior and cost.

Semantic TraceGraph turns an agent trace into a small, evidence-grounded task graph. The graph is a directed acyclic graph (DAG) whose nodes represent accomplishments supported by consecutive spans of the trace. In coding-agent traces, for example, a localization node can cover the searches and code reading that identify the relevant files and symbols. Edges capture causal relationships: an implementation node may depend on a localization node because the edit requires the earlier codebase understanding.

How it works

A lightweight decomposer agent constructs the graph from a trajectory. It can inspect selected events through a read-only Python sandbox rather than loading the entire trace into context. It then submits a candidate graph to a validator, which checks structural requirements such as valid evidence references and causal edges. The decomposer iterates within a fixed step budget until the graph is accepted. A separate judge agent then evaluates each node against the original trace.

Analysis

On a small matched subset of SWE-Bench-style coding traces from Claude-Opus-4.7, GPT-5-mini, Gemini-3-Pro, and DeepSeek-v3.2, we observe distinct debugging patterns. Claude-Opus-4.7 often moves directly from localization to implementation, while Gemini-3-Pro and DeepSeek-v3.2 more often follow an explicit localization, reproduction, and implementation sequence. These preliminary differences suggest that trace graphs can reveal how agents approach a task, not only whether they eventually solve it.

Status

This is an early prototype with a working ingest, decompose, verify, and evaluate pipeline on SWE-Bench-style coding traces.

Using the prototype

Clone the repository, install with pip install -e '.[dev]', and set TRACEGRAPH_API_KEY. The CLI entry point is tracegraph (audit, sample, decompose, verify, evaluate). Details are in the README.
